# 项目过程文档规则

本规则约束项目 `docs/` 中的过程文档。它规定文档如何组织、索引和维护，
不规定具体项目事实，也不管理项目根目录的 `README.md`。

新项目首次创建或重建 `docs/README.md` 时，可复制
`.spec/rules/templates/docs-readme.md` 作为结构起点；模板中的占位必须根据项目事实
替换或标记为“当前不适用”，不能直接当作已确认内容。

## 入口与职责

- `docs/README.md` 是当前项目过程文档的唯一地图和阅读指南，由项目维护。
- 需求、架构、测试、roadmap、checkpoint 和 postmortem 等正文放在对应目录，
  不把正文堆进 `docs/README.md`。
- 新增、移动、重命名、废弃或删除 `docs/` 文档后，必须同步更新
  `docs/README.md` 的路径、状态和阅读入口。
- `docs/README.md` 中的状态必须区分“已确认”“草案”“待补齐”和“当前不适用”，
  不得把模板占位伪装成项目事实。

## 维护流程

1. 先阅读项目级 agent 入口和现有 `docs/README.md`，确认事实源与文档边界。
2. 再按文档类型阅读本目录下对应的规则（requirements、architecture、testing 等）。
3. 只在权威事实源中修改正文，并在同一变更中更新 `docs/README.md` 地图。
4. 检查地图中的路径真实存在，或明确标记为待补齐/当前不适用。

根目录 `README.md` 是项目自行维护的产品或工程说明；除非项目自身规则或用户目标
明确要求，不要因为更新过程文档而修改它。

## 完成标准

- agent 能从 `docs/README.md` 找到需求、架构、测试和运行过程文档的权威位置；
- 文档地图不包含需求正文、任务计划、验证流水、run 日志或审查报告正文；
- 同一事实只有一个权威来源，其他位置使用链接而不是复制维护。
