# 项目 Agent 协作契约

> 本文件是项目级规则的唯一 agent 入口。首次项目会话必须把“待补齐”内容替换为真实项目事实。

## 适用范围

本文件适用于整个仓库。更深层目录中的 `AGENTS.md` 可以补充局部规则，但不得放宽
本文件中的安全、验证和事实源约束。普通开发任务不以修改本文件为默认目标；只有
项目协作契约发生变化时才维护它。

## 项目身份

- 项目名称：待补齐
- 项目目标：待需求澄清后补齐
- 当前阶段：探索 / 设计 / 实现 / 维护 / 迁移（待确认）
- 明确非目标：待需求澄清后补齐
- 主要维护者和使用者：待补齐

## 项目结构与契约

- 源码入口与模块边界：待补齐（列出主要目录及其职责）
- 测试入口与测试分层：待补齐（单测、集成测试、端到端测试）
- 生成文件与不可手改文件：待补齐
- 稳定接口/数据契约：待补齐（CLI、API、配置、schema、文件格式等）
- 依赖、运行时和版本约束：待补齐
- 配置、secrets 和本地环境边界：不得提交凭据；其余项目规则待补齐

## 开发与验证

- 安装依赖：待补齐
- 本地运行：待补齐
- 最小直接检查：待补齐
- 完整检查：待补齐
- 构建/发布：待补齐

代码或脚本变更必须先运行最小直接检查，再运行项目声明的完整检查；文档、配置、
生成物、软链和发布入口也必须验证实际行为。报告必须区分通过、失败、环境阻塞和
未验证范围。

## 工作流程

1. 先读本文件、`docs/README.md` 和当前任务事实源，确认项目边界与验证入口。
2. 涉及需求、方案或公开契约变化时，先更新对应权威文档，再实施代码。
3. 修改后先运行最小直接检查，再运行完整检查；完成时同步文档地图。
4. 任务结束时报告修改范围、验证结果、未验证项、生成物/外部影响和后续动作。

## 事实源与文档

- 项目过程文档唯一入口：`docs/README.md`；按地图进入需求、架构、测试、研究、复盘或 checkpoint。
- 协作规范入口：`.spec/README.md`；任务路由和规则由 Spec 体系维护。
- 项目产品/工程说明：`README.md`，由项目自行维护。
- 当前任务事实源：由项目入口确认后填写。

新增、移动、重命名或归档 `docs/` 文档时同步更新 `docs/README.md`；不要把正文或运行日志堆进本文件。

## Git 与安全

- 分支、提交和生成物交付约定：待补齐。
- 是否允许 agent 创建 commit：待补齐。
- 不猜测高影响需求；无法独立决策时提出人工决策项。
- 不读取或提交不应暴露的 secrets、凭据或生产数据。
- 删除数据、扩大权限、修改外部系统或重写历史前必须有明确授权和可回滚方案。
- 遇到需求冲突、破坏兼容性、数据迁移、权限扩大、删除/覆盖数据、生产环境操作或
  无法验证的关键行为时，停止扩大修改范围并提出待人工决策项。

## Spec / Ralph 集成

本项目使用 `.spec/` 作为协作规范和质量门；需要判断任务类型和适用规则时，先阅读
`.spec/README.md`。需要启动、配置、查看状态或排障 Ralph 时，先阅读 `.ralph/README.md`。
Ralph 的 oneshot 协议和任务调度由 `.ralph/` 自身管理，本文件不复制其内部逻辑。
